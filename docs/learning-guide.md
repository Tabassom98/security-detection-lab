# Make this portfolio your own

Before describing this as a skill in an interview, run the demo and tests yourself and explain the code in your own words. The starter was AI-assisted; your subsequent investigation and changes should be documented accurately.

1. Trace one alert to its event IDs and explain why a success does not prove compromise.
2. Change a timestamp to test the 300-second boundary. Explain why it counts.
3. Add a negative fixture for service-account typos and document tuning tradeoffs.
4. Implement a distinct-user rule with tests that distinguish spraying from repeated attempts against one account.
5. Keep dated notes describing actual work performed and remaining uncertainty.

Longer-term AI security direction: build a separate offline evaluation harness for prompt-injection scenarios using synthetic inputs, explicit expected outcomes, and reproducible results. Do not describe that as an implemented feature of this repository.
